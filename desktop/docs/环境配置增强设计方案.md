# 环境配置增强设计方案

## 1. 现状分析

当前 QM-Testing 的环境配置流程：

1. **环境识别阶段**：`EnvAnalyzerAgent` 在管道中扫描录制数据，提取 baseURL、认证方式、域名统计
2. **手动配置入口**：PipelinePage 提供"环境配置"按钮弹出 `EnvForm`，允许用户手动输入环境参数
3. **自动关联**：LinkerAgent 利用环境信息辅助跨接口关联，但环境信息与 Linker 的解耦不够

### 现有问题

- 环境识别结果（env-config.json）与 UI 配置割裂，未自动填充
- 环境配置仅作为 UI 输入，未有效传递到后续链路
- 缺乏全局请求头/全局 Cookie 配置能力
- 环境识别前后没有可视化状态指示
- 无环境变量引用系统，无法在请求头/请求体中引用环境变量

## 2. 设计目标

1. 环境识别结果**自动填充**到环境配置表单
2. 环境配置表单支持**全局请求头**和**全局 Cookie** 编辑
3. 环境配置数据**自动传递**给 Linker 和 Assembler，在用例层面注入
4. **可视化状态指示**：已识别/待识别/无环境
5. 支持**环境变量引用**语法 `${env.xxx}` 在请求中引用配置值

## 4. 详细设计

### 4.1 环境识别自动填充

**触发时机**：管道「环境识别」阶段完成后

**流程**：
1. EnvAnalyzer 输出 `env-config.json` 到 outDir
2. PipelinePage 的 `handleStart` 在管道完成后自动读取 `env-config.json`
3. 读取到的环境配置自动设置到 `envConfig` 状态
4. pipelineStore 同步更新 `envConfig` 字段
5. 环境配置表单自动显示已填充的数据

**数据结构**（env-config.json）：
```json
{
  "name": "TEST 环境",
  "baseURL": "https://api.example.com",
  "authType": "token",
  "authConfig": {
    "tokenPath": "data.token",
    "loginEndpoint": "/api/login",
    "globalHeaders": {
      "X-Requested-By": "QM-Testing"
    }
  },
  "domains": [
    { "domain": "https://api.example.com", "count": 23 }
  ]
}
```

### 4.2 环境配置表单增强

在现有 EnvForm 基础上增加：

1. **全局请求头编辑器**：JSON 格式的 key-value 输入框，支持变量引用
2. **全局 Cookie 编辑器**：可配置 Cookie 的 key/value，自动合并到每个请求的 Cookie header
3. **环境摘要显示**：管道运行后，在 PipelinePage 显示已识别环境的摘要信息
4. **状态指示器**：
   - 未识别 → 橙色 badge "待识别"
   - 已识别 → 绿色 badge "已识别"

### 4.3 环境变量引用系统

**语法**：`${env.变量名}`

**支持的变量来源**：
- `env.baseURL` → 环境的 baseURL
- `env.authType` → 认证方式
- `env.globalHeaders.xxx` → 全局请求头中的某个值
- `env.authConfig.xxx` → 认证配置中的值

**应用场景**：
- 在全局请求头中引用：`${env.baseURL}` 作为 `Origin`
- 在请求体中引用环境配置

### 4.4 环境配置传递链路

```
env-config.json ──→ PipelinePage (自动填充)
                       │
                       ▼
                   pipelineStore.envConfig
                       │
         ┌─────────────┼─────────────┐
         ▼             ▼             ▼
    PipelinePage   ReviewPage   RegressionPage
    (显示摘要)     (配置审查)   (试跑时注入环境)
```

### 4.5 试跑引擎环境注入

RegressionPage 在执行试跑时需要将环境配置注入到 HTTP 请求中：

1. 读取 `envConfig` 中的 `globalHeaders`，合并到每个 API 请求头
2. 替换请求中的 `${env.xxx}` 引用为实际值
3. 自动添加 Cookie header（如果配置了）

## 5. 实现步骤

1. ✅ **EnvForm 增强**：添加全局请求头编辑器
2. ✅ **PipelinePage 自动填充**：管道完成后读取 env-config.json 并自动填充
3. ✅ **状态指示器**：环境配置按钮显示已识别/待识别状态
4. ✅ **环境变量替换引擎**：在请求前替换 `${env.xxx}` 引用（RegressionRunnerAgent 中实现）
5. ✅ **试跑引擎环境注入**：将 globalHeaders/Cookie 注入到每个试跑 HTTP 请求中，不覆盖已有值

## 6. 预期效果

1. 用户导入录制 → 启动管道 → 环境识别自动完成 → 环境配置自动填充
2. 用户可以查看和编辑自动填充的环境配置（修改 baseURL、添加全局头等）
3. 全局请求头/Cookie 自动应用到所有接口，无需手动修改每个接口
4. 环境状态一目了然：已识别/待识别状态指示
5. 试跑验证时自动使用环境配置，保证请求一致性

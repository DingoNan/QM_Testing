# QM-Testing 使用手册

> 浏览器录制 API 请求 → 多 Agent 流水线自动化生成 API 测试用例

---

## 1. 产品简介

QM-Testing 是一个浏览器录制驱动的 API 测试用例生成工具。通过 **Tampermonkey 脚本** 录制浏览器中的 API 请求，经 **桌面端流水线** 自动清洗、关联、拼装，最终生成可直接导入测试平台的标准用例。

### 核心链路

```
浏览器操作 → Tampermonkey 录制 → JSON 文件导出
                                         ↓
                          ┌── Cleaner（数据清洗）
                          │   - 过滤噪音请求
                          │   - URL 归一化去重
                          │   - 按时间排序重编号
                          │   - 自动提取环境信息
                          │
                          ├── Env Analyzer（环境识别）
                          │   - 推断 baseURL / 认证方式 / Token 路径
                          │   - 等待用户确认补充
                          │
                          ├── Linker（跨接口关联）
                          │   - 构建响应值索引
                          │   - 自动替换 URL / Body / Header 引用
                          │   - 生成依赖关系图
                          │
                          ├── Assembler（用例拼装）
                          │   - 构建标准 CaseVo 格式
                          │   - 添加默认断言
                          │
                          ├── Reviewer（智能审查，Phase 2）
                          ├── Regression Runner（试跑验证，Phase 3）
                          └── Exporter（平台导出）
                                → 输出 case-save.json / 导入测试平台
```

### 2.3 安装步骤

**① 安装 Tampermonkey 录制脚本**

1. Chrome/Edge 安装 [Tampermonkey 扩展](https://www.tampermonkey.net/)
2. 打开扩展管理面板 → 新建脚本 → 将 `recorder/api-recorder.user.js` 内容粘贴
3. 保存脚本（`Ctrl+S`）
4. 访问任意网站，Tampermonkey 图标应显示脚本已启用

**② 安装桌面端依赖**

```bash
cd desktop
npm install
```

> 注意：`electron` 和 `electron-builder` 为 devDependencies，`npm install` 会自动安装。

**③ 启动桌面端**

```bash
cd desktop
npm run dev
# 或 python -m http.server 并手动加载渲染页面
```

## 3. 快速开始

以下以测试项目 **http://172.16.21.242:8080/** 为例，完整演示从录制到生成用例的全过程。

### 3.1 准备录制环境

1. 确保 Tampermonkey 中 **QM-Testing API Recorder** 脚本已启用
2. 访问 http://172.16.21.242:8080/
3. 页面右上角会出现录制工具栏（由 Tampermonkey 脚本注入）

### 3.2 登录系统

1. 在 http://172.16.21.242:8080/ 的登录页面输入：
   - **用户名**: `admin`
   - **密码**: `1`
2. 点击登录
3. Tampermonkey 脚本会自动捕获登录请求（包括用户名密码和返回的 Token）

### 3.3 执行操作

登录后，按测试需求在系统中执行一系列操作，例如：

- 浏览列表页面
- 查看详情
- 新增/编辑/删除数据
- 查询搜索

脚本会自动录制所有 API 请求（XHR / Fetch），自动过滤掉静态资源、监控请求等噪音。

### 3.4 导出录制 JSON

1. 点击 Tampermonkey 工具栏的 **"导出录制"** 按钮

### 3.5 导入桌面端

1. 启动 QM-Testing 桌面端：
   ```bash
   cd desktop
   npm run dev
   ```
2. 左侧导航栏点击 **"导入录制"**
3. 点击选择文件区域或拖拽刚才导出的 JSON 文件
4. 系统自动解析并显示预览：场景数、接口数、HTTP 方法、域名等统计信息
5. 确认无误后点击 **"启动管道处理"**

### 3.6 管道处理

桌面端自动按以下顺序处理：

| 阶段 | 处理内容 | 状态 |
|------|---------|------|
| 数据清洗 | 过滤噪音、去重、排序、重编号 | 自动 |
| 环境识别 | 检测 `baseURL=http://172.16.21.242:8080`、`authType=token`、`tokenPath=data.token` | 自动 + 用户确认 |
| 跨接口关联 | 自动将后续请求中的 Token/ID 替换为 `${seq.path}` 引用 | 自动 |
| 用例拼装 | 构建 CaseVo 标准格式，添加默认断言 | 自动 |

在 **环境识别** 阶段，系统会弹出确认对话框，显示自动检测到的环境信息：
- **Base URL**: `http://172.16.21.242:8080`
- **认证方式**: `token`
- **Token 路径**: `data.token`
- **域名列表**: `172.16.21.242:8080 (5 次请求)`

如需修改可直接编辑并保存。

### 3.7 查看与导出结果

处理完成后，在左侧导航栏点击 **"导出/导入"** 查看生成的用例摘要：
- **用例名称**: 自动从 API 路径推断
- **接口数**: 清洗后的有效接口数量
- **依赖边**: 自动发现的字段引用关系数量

可以：
- **导出 JSON**: 保存为标准用例文件
- **导入平台**: 直接导入 MeterSphere 等测试平台

此时在录制文件的同级目录下会生成 `out/` 目录，包含所有中间结果：


## 4. 详细使用指南

### 4.1 Tampermonkey 录制脚本

#### 录制控制

| 操作 | 说明 |
|------|------|
| 启用/暂停录制 | 通过脚本菜单切换 |
| 设置场景名称 | 录制前输入场景标识，便于区分 |
| 导出录制数据 | 导出为 JSON，自动过滤噪音 |
| 清空录制数据 | 开始新场景录制前清空 |

#### 录制规则

- 自动监听 `XMLHttpRequest` 和 `fetch()` 请求
- 过滤规则：静态资源（css/png/jpg...）、监控类（analytics/monitor/sentry...）、心跳（heartbeat/ping...）、开发工具（webpack/hmr/hot-update...）
- 最大记录数：2000 条（防内存溢出）
- 每次请求记录：URL、Method、Headers、RequestBody、ResponseBody、Status、Duration、Timestamp

### 4.2 桌面端使用

#### 导入录制（ImportPage）

支持两种导入方式：
1. **点击选择**：点击虚线区域弹出文件选择对话框
2. **拖拽导入**：直接将 JSON 文件拖入虚线区域

导入后自动显示：
- 场景数量与名称
- 接口总数
- 请求方法列表
- 关联域名统计
- 每条记录的详细信息（URL、Method、Status、Request/Response）

点击 "启动管道处理" 开始自动化流程。

#### 管道处理（PipelinePage）

显示处理进度：
- 每个阶段的名称和描述
- 实时进度百分比
- 处理状态（进行中/完成/失败）

处理完成后显示：
- **清洗后接口数**: 原始记录数 - 噪音数 - 重复数
- **关联后接口数**: 经过跨接口引用替换后的记录数
- **用例接口数**: 最终生成的标准 API 用例数
- **环境配置**: 自动提取的 baseURL、认证方式、Token 路径、域名统计
- **编辑环境**: 支持对环境配置进行修改后保存

#### 结果导出（ExportPage）

- **JSON 导出**: 以 JSON 格式保存完整用例
- **CSV 导出**: 以 CSV 格式导出用例摘要
- **导入平台**: 输入测试平台地址和 Token 直接导入（兼容 MeterSphere 接口 `/caseImport/saveOne`）

### 4.3 CLI 模式使用

适合无头环境或 CI/CD 集成。

```bash
# 1. 清洗
python scripts/clean.py recording.json --out out/

# 2. 关联
python scripts/link.py out/cleaned.json --out out/linked.json

# 3. 拼装
python scripts/build.py out/linked.json --project-id 1 --env 1 --out out/case-save.json

# 4. （可选）导入平台
python scripts/import.py out/case-save.json --url http://172.16.21.242:8080 --token your-token
```

**CLI 完整流水线一键执行**：

```bash
# Windows PowerShell
$inFile = "recording.json"
$outDir = "out"

python scripts/clean.py $inFile --out $outDir
python scripts/link.py "$outDir/cleaned.json" --out "$outDir/linked.json"
python scripts/build.py "$outDir/linked.json" --project-id 1 --env 1 --out "$outDir/case-save.json"

Write-Host "用例已生成: $outDir/case-save.json"
```

**查看平台项目列表**：

```bash
python scripts/import.py case-save.json --url http://172.16.21.242:8080 --token xyz --list-projects
```

## 5. 示例场景

### 场景：对 http://172.16.21.242:8080 项目生成完整测试用例

**目标**：录制用户在项目管理系统中的操作流程，生成可重放的 API 测试用例。

**步骤**：

1. 启动 Tampermonkey 录制
2. 打开 http://172.16.21.242:8080/
3. 使用 `admin / 1` 登录
4. 执行业务操作（如创建项目、查询列表、修改配置）
5. 退出登录
6. 导出录制 JSON → `recording_172_16_21_242.json`
7. 启动 QM-Testing 桌面端 → 导入录制文件
8. 启动管道处理
9. 在导出页面查看生成的用例并导出

**预期输出**（`case-save.json` 结构）：

```json
{
  "name": "Post 登录 等 6 个接口",
  "type": 1,
  "projectId": 1,
  "environment": 1,
  "domainName": "http://172.16.21.242:8080",
  "apiCount": 6,
  "apiVos": [
    {
      "orderNum": 1,
      "apiName": "Post Login",
      "apiMethod": "POST",
      "apiUrl": "/api/auth/login",
      "requestHeaders": "{\"content-type\":\"application/json\"}",
      "requestBody": "{\"username\":\"admin\",\"password\":\"1\"}",
      "assertVos": [
        {"expression": "responseBody.code", "expectValue": "0", "validateType": 3}
      ]
    },
    {
      "orderNum": 2,
      "apiName": "Get List",
      "apiMethod": "GET",
      "apiUrl": "/api/project/list",
      "requestHeaders": "{\"token\":\"${1.responseBody.data.token}\"}",
      "assertVos": [
        {"expression": "responseBody.code", "expectValue": "0", "validateType": 3}
      ]
    }
  ]
}
```

> 注意：第二个接口的 `token` 字段已被自动替换为 `${1.responseBody.data.token}`，表示其值来源于第 1 个接口的响应体。这种引用保证在重放时按正确顺序获取 Token。

## 6. 输出文件参考

| 文件 | 说明 | 关键字段 |
|------|------|---------|
| `cleaned.json` | 清洗后的接口列表 | `seq, method, url, domain, path, status, requestHeaders, requestBody, responseBody` |
| `env-config.json` | 环境配置 | `baseURL, authType, authConfig.tokenPath, domains` |

| `case-save.json` | 最终用例（可导入平台） | `name, projectId, environment, domainName, apiCount, apiVos` |

## 7. 常见问题

### Q1: 录制脚本不工作？

- 确认 Tampermonkey 扩展已启用
- 确认 **QM-Testing API Recorder** 脚本已安装且启用
- 打开浏览器开发者工具（F12）→ 控制台，查看是否有报错信息
- 确认 `@match` 规则覆盖了目标网站（默认为 `*://*/*` 即匹配所有网站）

### Q2: 录制数据太大？

- 默认最大记录数为 2000 条
- 如需调整，修改 `recorder/api-recorder.user.js` 中的 `CONFIG.maxRecords`
- 导出后可在 `cleaned.json` 中查看过滤后的有效数据

### Q3: 管道处理失败？

- 确认录制 JSON 格式正确（至少包含有效的 `method` 和 `url` 字段）
- 在管道页查看具体哪个阶段失败及错误信息
- 常见原因：空输入数据、文件路径错误、权限不足

### Q4: 关联结果不准确？

- 检查 `env-config.json` 中的环境配置是否正确
- 确认 Token 类字段在响应体中的路径被正确识别
- 长字符串值的匹配需要至少后 16 位相同（子串匹配机制）
- 数值 ID 匹配要求值 >= 100（`_isMeaningfulValue` 过滤规则）

### Q5: 如何集成到 CI/CD？

```bash
# Jenkins / GitLab CI 脚本示例
node -e "
  const { CleanerAgent } = require('./desktop/agents/cleaner');
  const { LinkerAgent } = require('./desktop/agents/linker');
  const { AssemblerAgent } = require('./desktop/agents/assembler');
  // ... 在 Node.js 中直接调用 Agent API
"
```

或使用 Python CLI 流水线（见第 4.3 节）。

### Q6: 启动桌面端提示 "electron 模块未找到"？

```bash
cd desktop
npm install
```

首次使用需安装 Electron 依赖。

## 8. 技术架构

更多设计细节见 [QM-Testing_API自动化方案_55ee7a7f.md](./QM-Testing_API自动化方案_55ee7a7f.md)

### 核心模块

- **BaseAgent**: Agent 基类，统一生命周期（pending → running → completed/failed/waiting_user）
- **Orchestrator**: 管道编排器，支持顺序执行、异步分片、断点续传、状态持久化
- **Recording**: 录制数据模型，自动截断超 1MB 的响应体防止 OOM
- **CaseVo**: 用例模型，对齐测试平台标准格式

### 安全设计

- `contextIsolation: true` + `preload.js`（contextBridge）隔离渲染进程
- `nodeIntegration: false` 禁止渲染进程直接访问 Node.js API
- truncateBody() 保护机制防止大响应体 OOM

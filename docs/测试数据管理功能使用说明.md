# 测试数据管理功能使用说明

## 1. 概述

**测试数据池（Data Pool）** 是 QM-Testing 中管理外部测试数据的标准化模块，用于将测试数据与接口用例解耦。数据池支持三种来源（手动录入、CSV 文件、TXT 文件），提供字段级类型定义、行级启用控制、高级迭代策略等能力，并与管道处理（Pipeline）深度集成，实现数据驱动的测试执行。

数据池在以下场景中发挥作用：

- **参数化测试**：同一接口用不同数据反复执行
- **登录用户列表**：管理不同环境的测试账号
- **批量数据构造**：通过 CSV/JSON 批量导入测试数据
- **数据驱动回归**：展开模式每行生成独立用例，或循环模式逐行迭代

## 2. 数据池管理界面

### 2.1 进入数据池管理

在导航栏点击「测试数据管理」进入。页面加载后自动列出所有已保存的数据池。

### 2.2 数据池列表

每个数据池卡片显示：

- **名称**：数据池的名称
- **来源标签**：`manual`（手动录入）、`csv`（CSV 导入）、`txt`（TXT 导入）、`paste`（批量粘贴）
- **统计**：`x 字段, x 行`
- **标签**：逗号分隔的自定义标签

### 2.3 搜索与筛选

页面提供搜索输入框，可按数据池名称或标签进行实时模糊搜索。

### 2.4 展开详情

点击数据池卡片可展开详情面板，显示：

- **描述**：创建时填写的描述信息（如无则显示「暂无描述」）
- **高级控制**：超出行为、排序模式、共享模式
- **字段列表**：所有字段名及类型
- **变量引用格式**：展示 `${data.数据池名称.字段名}` 格式供复制
- **数据预览**：前 3 行实际数据（含启用状态）
- 数据行超过 3 行时显示「还有 x 行」提示

## 3. 创建数据池

### 3.1 新建入口

点击「+ 新建数据池」按钮，打开新建表单。

### 3.2 名称与描述

| 字段 | 说明 |
|------|------|
| 数据池名称 | 必填，建议简明表意（如：登录用户列表、商品查询参数） |
| 描述 | 可选，用于说明数据池用途 |
| 来源 | 自动生成，只读（manual/csv/txt/paste） |

### 3.3 字段定义

每个字段包含以下属性：

| 属性 | 说明 |
|------|------|
| 字段名 | 字段标识，在变量引用中使用（如 `${data.username}`） |
| 类型 | 支持 `string`、`number`、`boolean`、`json`、`expression 🔑` |
| 默认值 | 行数据中该字段为空时的回退值 |

操作：

- **添加字段**：点击「+ 添加字段」按钮
- **删除字段**：点击字段行右侧的 `X` 按钮（至少保留一个字段）
- **类型说明**：
  - `string`：字符串（默认）
  - `number`：数值，自动转换
  - `boolean`：布尔值，自动识别 `true/false/1/0`
  - `json`：JSON 对象，`parse` 后传入
  - `expression`：动态表达式，在运行时求值

### 3.4 数据行编辑

数据行表格支持以下操作：

- **添加行**：点击「+ 添加行」新增一行，字段值初始为默认值
- **编辑单元格**：直接输入
- **启用/禁用**：复选框控制该行是否参与迭代（禁用的行在运行时被跳过）
- **删除行**：点击行尾 `X` 按钮

### 3.5 高级控制

#### 超出行为

定义当迭代器读取数据行超过数据池行数上限时的行为：

| 选项 | 说明 |
|------|------|
| 重新从头读取 (recycle) | 从头开始重新取数（默认） |
| 只使用现有行 | 当索引越界时返回 null，停止取数 |
| 报错停止（stop on EOF） | 索引越界时直接报错 |

#### 排序模式

| 选项 | 说明 |
|------|------|
| 顺序读取 | 按行号递增获取（默认） |
| 随机取行 | 每次随机从启用的行中取一条 |

#### 共享模式

定义多实例并发时的数据访问策略：

| 选项 | 说明 |
|------|------|
| 所有实例共享 | 所有实例共用一个迭代计数器 |
| 当前实例独立 | 每个实例有自己的迭代计数器 |
| 每实例一份副本 | 每个实例持有完整的数据副本 |

> 注意：共享模式目前为预留设计，当前版本对所有实例均视为独立。

### 3.6 标签

逗号分隔的标签，用于搜索和分类。例如：`登录, 生产数据, 回归用`。

### 3.7 保存

点击「保存数据池」按钮完成创建。系统自动生成唯一 ID（格式：`pool_时间戳_随机数`），数据持久化到 `data/dataPools/pool_*.json` 文件中。

## 4. 导入数据

### 4.1 CSV 导入

1. 点击「导入数据」→ 切换到「CSV 文件」页签
2. 点击「选择文件并导入」，系统弹出文件选择对话框
3. 选择 CSV 文件（支持 `.csv`、`.txt` 扩展名）
4. 系统自动解析：
   - 首行为字段名（中文自动转为 `field_N` 别名形式）
   - 后续行为数据行
   - 自动推断字段类型（string/number/boolean/json）
5. 解析成功后打开新建表单，预览检测到的字段和数据

**CSV 格式要求**：
- 首行必须为字段名
- 支持逗号分隔
- 支持引号包裹字段（含逗号的字段需用双引号包裹）
- 支持 UTF-8 BOM 自动检测

### 4.2 TXT 导入

1. 点击「导入数据」→ 切换到「TXT 文件」页签
2. 点击「选择文件并导入」
3. 系统自动解析，规则同 CSV 类似，分隔符为空格或制表符

### 4.3 批量粘贴

1. 点击「导入数据」→ 切换到「批量粘贴」页签
2. 在文本框中粘贴数据（CSV 或 TXT 格式），支持逗号分隔、制表符分隔、JSON 数组格式
3. 移出焦点（blur）时自动触发解析
4. 解析成功后打开新建表单

**支持的数据格式示例**：

```csv
username,password,remark
admin,123456,管理员
guest,guest123,访客
```

```json
[
  {"username": "admin", "password": "123456"},
  {"username": "guest", "password": "guest123"}
]
```

## 5. 数据池详情查看

展开数据池卡片后，可查看以下信息：

### 5.1 变量引用格式

系统为每个字段自动生成变量引用格式：

```
${data.数据池名称.字段名}
```

示例：数据池名为「登录用户列表」，字段为 `usercode`，引用格式为：

```
${data.登录用户列表.usercode}
```

在管道的数据绑定向导中，字段映射时使用此格式从数据池取值。

### 5.2 数据预览

预览表格显示前 3 行数据，每行左侧有 ✓/✗ 标记表示该行是否启用。

## 6. 数据池与管道集成

### 6.1 数据绑定向导

管道处理完成后（所有阶段执行完毕），点击「数据绑定」按钮打开 DataBindingWizard（数据绑定向导），分为 4 个步骤：

#### 步骤 1：选择数据池

从已创建的数据池列表中选择数据源。列表显示字段数和行数。若无数据池，可点击「前往创建数据池」跳转到数据池管理页面。

#### 步骤 2：字段映射

将数据池字段映射到接口参数：

- **数据池字段**：下拉选择数据池中的字段
- **目标接口（Seq）**：填写接口序号（如 1, 2, 3）
- **目标位置**：选择映射到接口的哪个部分
  - `URL 参数`：替换 URL 中的 `{param}` 占位符
  - `请求头`：写入 `requestHeaders`
  - `请求体`：写入 `requestBody` 的对应字段
  - `断言预期值`：设置断言中的期望值
  - `断言表达式`：设置断言中的表达式
- **变量表达式**：默认生成 `${data.字段名}`，可自定义修改

**自动映射**：点击「🤖 自动映射」按钮，系统通过字段名相似度自动匹配接口中的同名参数。

#### 步骤 3：高级设置

| 设置项 | 选项 | 说明 |
|--------|------|------|
| 迭代模式 | 展开模式 / 循环模式 / 不启用 | 决定数据池数据如何作用于测试用例 |
| 超出行为 | 重新从头读取 / 停止取数 | 同数据池定义 |
| 排序模式 | 顺序读取 / 随机取行 | 同数据池定义 |
| 共享模式 | 全部共享 / 独立 / 副本 | 同数据池定义 |
| 最大行数限制 | 数字 | 限制参与迭代的最大行数（0 不限制） |

#### 步骤 4：预览与确认

在确认前可预览：
- 数据池名称、字段数、数据行数
- 将生成的用例数
- 所有字段映射详情（字段→接口→位置→表达式）

确认后，系统根据迭代模式执行对应的数据展开或绑定操作。

### 6.2 两种迭代模式

#### 展开模式（Expand）

- **原理**：N 行数据 → N 个独立的 CaseVo，每个 CaseVo 包含完整的一组 API 接口
- **流程**：重新运行 Assembler 代理，用数据池每行数据替换映射字段的值，生成 N 份用例
- **效果**：在 ReviewPage 中可通过下拉切换不同用例审核和编辑
- **适用场景**：每个数据行对应一个独立的测试场景

#### 循环模式（Loop）

- **原理**：1 个 CaseVo 携带 dataPoolConfig，RegressionRunner 逐行循环取数执行
- **流程**：数据池配置保存到 pipelineResult，回归运行时每轮迭代取一行数据注入上下文
- **效果**：在 RegressionPage 中显示数据池信息和当前迭代的行索引
- **适用场景**：同一组接口需要用不同数据反复执行验证

## 7. 回归测试集成

### 7.1 展开模式回归

- RegressionPage 自动检测 `caseVoList` 中的多用例列表
- 顶部下拉框可切换当前执行的用例（CaseVo）
- 运行回归时自动使用当前选中的 CaseVo

### 7.2 循环模式回归

- RegressionPage 检测 `iterationMode === 'loop'` 和 `dataPoolConfig` 时
- 调用 `runRegressionWithData` 接口，传入数据池配置和映射规则
- 执行时每轮迭代从数据池取一行，注入 `${data.字段名}` 变量到接口请求
- 结果卡片头部显示 `_rowIndex` 表示当前迭代的行索引
- 统计区显示数据池名称和总行数

## 8. 环境关联

### 8.1 数据池→环境

数据池模型包含 `envId` 字段，用于标识该数据池属于哪个环境。保存时可通过 `envId` 参数关联：

```javascript
// 保存数据池时传入 envId
window.appApi.dataPoolSave({
  ...poolData,
  envId: 'env_xxx'  // 环境 ID
});
```

### 8.2 环境→数据池

Environment 模型包含 `linkedDataPoolIds` 数组，用于记录该环境关联了哪些数据池：

```javascript
// Environment 构造函数
{
  linkedDataPoolIds: ['pool_xxx', 'pool_yyy']
}
```

### 8.3 当前状态

- 数据池列表摘要中会显示 `envId` 字段
- 数据池 JSON 文件持久化时包含 `envId`
- 环境配置与数据池之间的关联需要用户在管道绑定时手动建立

| 通道 | 方法 | 说明 |
|------|------|------|
| `dataPool:list` | 异步 | 列出所有数据池摘要（含 fieldCount/rowCount/envId） |

| `dataPool:importTxt` | 异步 | 打开文件对话框导入 TXT |

## 10. 常见问题

### Q: 显示「无预览数据」

这是数据池列表仅返回摘要信息导致的。展开卡片时会自动调用 `dataPool:get` 加载完整数据，加载后即可显示字段和数据预览。如果仍不显示，可能是网络或 IPC 通信异常，可查看控制台日志。

### Q: 手动录入的数据来源显示为 manual

`manual` 来源表示数据是手动通过「新建数据池」表单录入的，并非从文件导入。这是正常行为。

### Q: 数据池和环境如何关联？

当前环境配置中可通过 `linkedDataPoolIds` 字段关联多个数据池。数据池本身也支持 `envId` 字段反向关联到环境。但在 UI 中建立关联需要通过管道的数据绑定向导（DataBindingWizard）完成。

### Q: 展开模式和循环模式如何选择？

- 如果你的数据每一行代表一个完整的测试场景（如不同用户的 API 调用链路），使用**展开模式**
- 如果你的数据是同一组接口的参数变化（如用不同账号反复测试登录接口），使用**循环模式**

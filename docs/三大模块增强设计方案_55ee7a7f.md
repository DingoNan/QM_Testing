# 三大模块增强设计方案

## 总览

本次涉及三个模块的增强：
1. **导入录制** — 从只读预览变为可编辑编辑器
2. **跨接口关联** — 自动关联存在但用户不可见，需补充可视化层
3. **智能审查** — 增加 API 编辑、AI 优化、规则 CRUD

---

## 一、导入录制增强 (ImportPage.js + Recording.js)

### 现状
- ImportPage 只显示只读的场景卡片列表 + 统计
- 无法编辑场景名称、无法删除/修改单个接口

### 设计方案

#### 数据结构（Recording.js 增强）
```
Scenario:
  id, name (可编辑)
  records[]:
    seq, time, method, url, status
    requestHeaders, requestBody, responseBody (保留原始数据用于参考)
    enabled: true   // 新增：标记是否启用（删除 = 标记为 false）
    ref: string     // 新增：用户备注/引用
```

#### UI 布局（ImportPage.js 改造）

**导入后视图分为三栏：**

```
┌─────────────────────────────────────────────┐
│ [场景名称编辑]  [批量删除]  [批量保存]       │
├─────────────────────────────────────────────┤
│ 场景列表 (左侧)  │  接口详情 (右侧)          │
│ ┌──────────────┐ │ ┌──────────────────────┐ │
│ │ 场景1 ✓  [×] │ │ │ Method: [GET ▼]     │ │
│ │ 场景2 ✗  [×] │ │ │ URL: [__________]   │ │
│ │ 场景3 ✓  [×] │ │ │ Headers: [_________] │ │
│ └──────────────┘ │ │ Body: [____________] │ │
│  [+ 添加场景]     │ │ Status: 200          │ │
│                   │ │ Duration: 320ms      │ │
│ 勾选=启用         │ │ [删除] [保存] [取消]  │ │
│                   │ └──────────────────────┘ │
└─────────────────────────────────────────────┘
```

#### 关键功能点

1. **场景编辑**：场景名 inline 编辑（点击名称直接编辑）
2. **接口列表**：
   - Checkbox 多选 + 全选
   - 点击行查看详情/编辑
   - 过滤：按 method、按 URL 关键字搜索
3. **接口编辑弹窗/面板**：
   - Method (下拉选择 GET/POST/PUT/DELETE 等)
   - URL (可编辑)
   - Request Headers (JSON 编辑器)
   - Request Body (JSON 编辑器)
   - 原始响应体 (只读参考)
4. **批量操作**：
   - 批量删除选中
   - 批量启用/禁用
   - 批量保存到 store
5. **数据保存**：
   - 编辑后立即更新 pipelineStore 中的 recording
   - "批量保存"写入 `outDir/import-edited.json` 持久化

#### 涉及的文件

| 文件 | 改动 |
|------|------|
| `renderer/pages/ImportPage.js` | 重写——从只读变为完整编辑器 |
| `models/Recording.js` | 添加 `enabled`、`ref` 字段 |
| `main/ipc-handlers.js` | 新增 `recording:saveEdits` handler |
| `main/preload.js` | 新增 `saveRecordingEdits` API |

## 二、跨接口关联增强 (Linker 可视化)

### 现状
- LinkerAgent 已经实现了**自动关联引擎**（响应值索引构建、URL ID 替换、请求体字段引用替换、鉴权 header 强制替换、依赖图构建）
- 但关联结果对用户**完全不可见**——只能通过查看 `linked.json` / `deps-graph.json` 文件了解
- 用户无法确认关联是否正确，也无法手动干预

### 设计方案

#### 2.1 关联结果可视化页面

**在 pipeline 完成后添加一个 "查看关联详情" 按钮/页面**，展示 Linker 的输出：

```
┌─────────────────────────────────────────────┐
│ 跨接口关联详情          [手动编辑关联关系]   │
├─────────────────────────────────────────────┤
│ 依赖图 (DAG)                                │
│                                             │
│  [login POST] ──token──▶ [user GET]        │
│       │                    │                │
│       ├──userId──▶ [order POST]             │
│       │                                     │
│       └──session──▶ [list GET]              │
│                                             │
├─────────────────────────────────────────────┤
│ 接口关联明细                                 │
│ ┌──────┬──────┬──────────┬─────────┬──────┐ │
│ │ 序号 │ 接口  │ 来源     │ 替换内容 │ 类型 │ │
│ ├──────┼──────┼──────────┼─────────┼──────┤ │
│ │ 3    │ GET   │ Seq 1   │ token   │ auth │ │
│ │      │ /user │ data.tok│ ${1...} │      │ │
│ └──────┴──────┴──────────┴─────────┴──────┘ │
└─────────────────────────────────────────────┘
```

#### 2.2 手动关联编辑

用户可以在可视化界面中：
1. **查看自动发现的依赖关系**（来自 deps-graph.json）
2. **手动添加关联规则**：如 "接口 5 的 header.X-Token 引用接口 1 的 responseBody.data.token"
3. **删除/修改关联规则**
4. **重新生成 linked.json**（应用手动修改后的规则）

#### 2.3 LinkerAgent 增强

新增 **`manualDeps`** 参数，允许传入用户手动定义的依赖规则：

```javascript
// 用户手动添加关联示例
{
  fromSeq: 1,           // 来源接口序号
  fromPath: 'responseBody.data.token',  // 来源字段路径
  toSeq: 5,             // 目标接口序号
  toLocation: 'requestHeaders.X-Token', // 目标位置
  matchType: 'manual'
}
```

LinkerAgent.execute() 自动关联 + 应用手动规则 → 输出最终的 linked.json。

#### 2.4 关联 Dashboard 页面

**新建页面：`LinkerViewPage.js`** 或在 PipelinePage 完成后增加 "查看关联" 按钮跳转。

| 文件 | 改动 |
|------|------|
| `agents/linker.js` | 新增 `manualDeps` 参数支持，execute 同时处理自动+手动规则 |
| `renderer/pages/LinkerPage.js` | **新建**——依赖图可视化 + 手动关联编辑 |
| `renderer/app.js` | 新增路由到 LinkerPage |
| `main/ipc-handlers.js` | 新增 `linker:getDeps` / `linker:applyManualDeps` |
| `main/preload.js` | 新增 linker API |

## 三、智能审查增强 (ReviewPage.js + reviewer.js)

### 3.1 API 编辑（批量删除与修改）

**ReviewPage 的 API 列表增加编辑功能：**

- 每个 API 卡片增加 Checkbox（多选支持）
- 工具栏增加：
  - "删除选中" 按钮
  - "批量修改" 按钮（弹窗批量修改 Method/URL/Headers）
- 展开详情后，Headers 和 Body 变为可编辑（JSON 编辑器）
- "保存修改" 更新 pipelineResult.caseVo

### 3.2 AI 优化功能

**审查完成后，增加 "AI 优化" 按钮：**

1. 用户执行审查（规则 + AI）
2. 看到审查结果和建议
3. 点击 "AI 优化" → 将审查发现的问题 + 用例数据发送给 AI
4. AI 返回优化后的用例（修复断言、补充缺失字段等）
5. 用户确认/Accept/Reject 变更

需要新增 reviewer.js 中的 `_aiOptimize()` 方法，以及 IPC handler `review:optimize`。

### 3.3 规则 CRUD（新增/删除/修改审查规则）

#### 现状
- 6 条内置规则硬编码在 `reviewer.js` 的 `BUILTIN_RULES` 数组中
- 用户只能启用/禁用
- 无法新增、删除、修改规则

#### 设计方案

**规则存储**：将规则定义存储在 `data/review-rules.json` 文件中

**规则数据结构**：
```javascript
{
  id: 'MY_CUSTOM_RULE',      // 规则唯一 ID
  name: '自定义规则',          // 显示名称
  description: '检查接口...',  // 描述
  severity: 'error',          // error / warning / info
  enabledByDefault: true,
  config: {},                 // 自定义参数
  isBuiltin: false,           // true=内置不可删除, false=自定义可删除
  // 自定义规则的检查逻辑存储为模板字符串
  checkTemplate: `(api, apiIndex, context) => {
    // 用户自定义的 JS 逻辑
    return api.apiUrl.includes('test') 
      ? { pass: false, message: 'URL 包含 test' }
      : null;
  }`
}
```

**规则编辑器 UI**：
```
┌──────────────────────────────────────────────┐
│ 规则管理                     [+ 新增规则]     │
├──────────────────────────────────────────────┤
│ ┌─────────┬──────┬──────┬──────────────────┐ │
│ │ 规则名称 │ 级别  │ 来源 │ 操作             │ │
│ ├─────────┼──────┼──────┼──────────────────┤ │
│ │ 状态码   │ error│ 内置 │ [编辑]           │ │
│ │ 最少断言 │ warn │ 内置 │ [编辑]           │ │
│ │ 自定义1  │ info │ 用户 │ [编辑] [删除]    │ │
│ └─────────┴──────┴──────┴──────────────────┘ │
│                                               │
│ --- 新增/编辑规则弹窗 ---                      │
│ 名称: [________________]  级别: [error ▼]     │
│ 描述: [________________]                      │
│ 逻辑:                                         │
│ ┌──────────────────────────────────────────┐ │
│ │ // 返回 null=通过，返回 {pass,message}=失败 │ │
│ │ if (api.assertVos.length === 0) {        │ │
│ │   return { pass: false, message: '...' } │ │
│ │ }                                         │ │
│ │ return null;                              │ │
│ └──────────────────────────────────────────┘ │
│ [保存] [取消]                                 │
└──────────────────────────────────────────────┘
```

## 实施优先级建议

**Phase 1（最优先——导入编辑）**
- ImportPage 增强：场景名编辑、接口查看/删除、批量操作
- 这是最基础的编辑能力，对用户价值最高

**Phase 2（次优先——审查增强）**
- ReviewPage 增加 API 编辑/批量删除
- AI 优化功能
- 规则 CRUD（规则编辑器优先）

**Phase 3（关联可视化）**
- LinkerPage 新建：依赖图可视化
- 手动关联编辑
- 此功能依赖前两个阶段的数据稳定性

## 不修改的部分

- 已有的自动关联引擎逻辑（`_buildResponseIndex`、`_lookupValue` 等）保持不变
- CleanerAgent、EnvAnalyzerAgent、AssemblerAgent 逻辑不变
- Orchestrator 不变
- 导航路由架构不变

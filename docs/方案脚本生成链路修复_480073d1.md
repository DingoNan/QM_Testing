# 方案与脚本生成链路修复计划

## 问题描述

创建测试场景时，接口 body（如 `{"username":"admin","password":"1"}`）在生成测试脚本后被替换为其他值（如 `{"username":"test","password":"test123"}`）。这是因为 body/header 数据在从"接口定义 → 方案(plan) → 脚本"的链路中丢失。

## 根因

三层贯穿问题：
1. `planning_agent.py` 的 `from_wizard()` 丢弃了接口的 `headers`、`body_template`、`query_params`
2. 规划Agent和设计Agent的 LLM 提示词不包含 body/header 数据，LLM 只能编造
3. 模板脚本生成器的登录方法硬编码了用户名密码

## 修改计划

### 阶段 1：修复模板路径数据管道

**文件：`sidecar/agents/planning_agent.py`**

1.1 `from_wizard()` (line 534-550): 传递 headers、body_template、query_params 到 ApiDefinition
- headers 从前端字符串（"Key: Value\\nKey2: Value"）解析为 dict
- body_template 从接口 body 字段直接取
- is_login_api 也从前端传入数据而非靠路径猜测

1.2 `from_yaml()` (line 698-754): 支持从 YAML 解析 headers 和 body
- 将 regex 解析改为使用 PyYAML（或增强 regex 支持 block scalar）
- 避免 LLM 生成的 YAML 中的 body/header 被丢弃

**文件：`sidecar/agents/design_agent.py`**

1.3 `_write_login_method()` (line 366-395): 使用实际 body 数据代替硬编码
- 解析 login_api 的 body_template JSON，提取 username/password 字段
- 保留环境变量兜底（`os.getenv("LOGIN_USERNAME", ...)`），先尝试 body 值

1.4 `generate_script()` (line 141-142 body_template 使用): 确保 JSON body 正确序列化
- 使用 `json.loads` 解析 body_template 再传参，而非直接字符串拼接
- 非 JSON body 直接传字符串

### 阶段 2：修复 LLM 提示词

**文件：`sidecar/agents/planning_agent.py`**

2.1 `_generate_with_llm()` (line 893-896): 在 prompt 中包含 headers、body、query_params
- 每个接口增加 `headers:` 段（显示 Key: Value 列表）
- 每个接口增加 `body:` 段（显示完整 body JSON，截断至 300 字符）
- 增加指令："使用提供的实际 body 和 headers 值，不要修改它们"

**文件：`sidecar/agents/design_agent.py`**

2.2 `_generate_with_llm()` (line 460-468): 在 prompt 中包含 body_template、headers
- 从 plan apis 中读取 body_template 和 headers 传给 LLM
- 添加约束："使用提供的精确 body 和 headers 值，禁止修改"
- 修改 system_prompt 为中英文混合说明（输出注释用中文）

### 阶段 3：修复 YAML 生成

**文件：`locust-agent/src/pages/ScenarioWizard.tsx`**

3.1 `generateYaml()` (line 218-268): 无需改动，已正确输出 body/headers

3.2 `handleSubmit()` (line 1004-1012): 在 wizardData.interfaces 中增加 `is_login_api` 字段

### 阶段 4：中文化与参数化基础

**文件：`sidecar/agents/design_agent.py`**

4.1 所有模板生成的中文注释：将 `# adjust credentials as needed` 改为 `# 使用实际登录凭据`
4.2 登录方法支持参数化 hint：当 body 中包含 ID/动态值时，在脚本中生成 `# TODO: 参数化`

**文件：`locust-agent/src/utils/curlParser.ts`**（无需修改，已在上一个任务中完成）

## 验证方法
1. 创建测试场景 → 粘贴 Windows cmd curl → 确认 body/headers 正确显示
2. 生成测试方案 → 确认 YAML 预览中 body/headers 存在
3. 生成测试脚本 → 确认脚本使用实际 body 值（`{"username":"admin","password":"1"}`）
4. 检查 LLM 模式 → 确认 LLM 不使用编造的参数值
5. 检查模板模式 → 确认登录方法使用 body 中的实际凭据

# 环境配置增强与接口参数串联 - 代码改造实施计划

## 一、基础 Model 层（新建 4 个文件）

### 1.1 ~~desktop/models/TestDataPool.js~~ (NEW) - 测试数据池模型
- Class `TestDataPool`: id, name, description, source('csv'|'txt'|'paste'|'manual'), fields[], rows[], tags[], createdAt
- Class `FieldDef`: name, type('string'|'number'|'json'|'boolean'), alias[], defaultValue, description
- Class `DataRow`: values{fieldName:value}, enabled
- 静态方法 `fromCSV(csvContent, opts)`: 首行表头→FieldDef，自动推断类型，支持 UTF-8 BOM，支持引号包裹字段
- 静态方法 `fromTXT(txtContent, opts)`: 分行+分割符或正则解析
- 实例方法 `toJSON()`, `validate()`: 数据完整性校验
- 高级控制属性 (CyclicMode): recycle, randomOrder, sharingMode
- CSV 解析支持 recycle/random/sharing 三种模式字段

### 1.2 ~~desktop/models/FunctionRegistry.js~~ (NEW) - 运行时函数注册表
- Class `FunctionRegistry`: 内置函数注册 + 用户自定义扩展
- 16 个内置生成函数: phone, email, idCard, randStr, randNum, uuid, timestamp, date, time, now, base64, md5, sha256, substring, concat, nowPlus
- 5 类运行时函数: 随机生成(RANDOM)/时间日期(TIME)/编码哈希(ENCODE)/字符串处理(STRING)/条件逻辑(COND)
- 方法 `register(name, fn, category, description)`, `call(name, ...args)`, `getHelp(name)`, `hasFunction(name)`, `listFunctions(category)`
- 函数表达式解析: `$sys.uuid` `$sys.phone(138)` 格式，支持嵌套 `${sys.concat(${data.prefix}, "_", ${sys.uuid})}`

### 1.3 ~~desktop/models/ChainRule.js~~ (NEW) - 串联规则模型
- Class `ChainRule`: id, name, sourceApiSeq, sourcePath, targetApiSeq, targetLocation('url'|'requestHeaders.'|'requestBody.'|'assert.N.expectValue'|'assert.N.expression'), transform
- Class `TransformDef`: type('none'|'jsonpath'|'regex'|'template'|'function'), expression, params{}
- 方法 `apply(sourceValue)` → 按 transform 类型处理

### 1.4 ~~desktop/models/VarResolver.js~~ (NEW) - 统一变量解析器（核心引擎）
- 支持 5 层命名空间: `$env.xxx` > `$seq.N.xxx` > `$data.xxx` > `$ctx.xxx` > `$sys.xxx`
- 支持嵌套函数调用: `$sys.concat(...)`
- 方法 `resolve(str, context)`: 解析字符串中所有变量引用
- 方法 `resolveObject(obj, context)`: 深度递归解析对象
- 方法 `replaceVarRefs(str, context)`: 单层变量替换
- 上下文接口: `{ envConfig, dataRow, seqResponses, ctxVars, linkedRecords, currentIndex, functionRegistry }`

## 二、Agent 层改造（修改 4 个文件）

### 2.1 ~~desktop/agents/regression-runner.js~~ (MAJOR) - 回归验证增强
- **循环迭代模式**: 当 `dataPoolId` 和 `iterationMode` 配置时，对每条数据行执行完整接口链
- **循环模式上下文**: ctx 变量在行间积累（同 JMeter ForEach Controller），行结束不清空
- **展开模式**: 每行数据生成独立 CaseVo，Assembler 阶段完成，Regression 无感
- **preRequest 前置脚本**: 在每个接口请求前执行用户脚本（可修改 env/ctx/data）
- **postResponse 后置脚本**: 在接口响应后执行（可设置断言、提取变量）
- **替换 `_replaceVarRefs`** 使用 `VarResolver` 替代当前简单的正则替换
- 新增 `data.*` 命名空间解析 → 从当前数据行取值

### 2.2 ~~desktop/agents/linker.js~~ (MINOR) - 关联引擎增强
- 新增 `chainRules` 处理: 在自动关联完成后，叠加用户配置的 ChainRule
- 输出时携带 chainRule 元信息

### 2.3 ~~desktop/agents/orchestrator.js~~ (MINOR) - 编排器增强
- 接受 `dataPoolConfig`, `chainRules`, `iterationMode` 等参数
- 在管道输入阶段传递给各个 Agent

### 2.4 ~~desktop/agents/assembler.js~~ (MINOR) - 用例拼装增强
- **展开模式 (expand)**: N 行数据 → N 个 CaseVo 写入 case-save.json
- **循环模式 (loop)**: 单个 CaseVo + dataPoolId 写入 case-save.json
- DataBindingWizard 生成的绑定信息注入 CaseVo.metadata

## 四、脚本引擎（新建 1 个文件）

### 4.1 ~~desktop/agents/ScriptEngine.js~~ - 前置/后置脚本引擎
- Class `ScriptEngine`: 基于 Node.js `vm` 沙箱执行
- 安全限制: 5 秒超时, 32MB 内存, 禁止 require/import/file IO
- `computePreRequest(script, context)` → 返回修改后的 context
- `computePostResponse(script, context)` → 返回断言更新
- 上下文对象: `{ env, ctx, data, sys, request, response, log, pm }`
- pm API: `pm.variables.set/get/clear`, `pm.expect(actual).to[be/contain/match]`

## 五、IPC + Preload 层（修改 2 个文件）

### 5.1 ~~desktop/main/ipc-handlers.js~~ - 新增 IPC 通道
- `dataPool:save` — 创建/更新数据池 (持久化到 data/dataPools/ 目录)
- `dataPool:list` — 列出所有数据池 (含摘要信息)
- `dataPool:get` — 读取单个数据池完整数据
- `dataPool:delete` — 删除数据池
- `dataPool:importCsv` — 导入 CSV 文件(弹窗选文件→解析→返回字段预览)
- `dataPool:importTxt` — 导入 TXT 文件
- `chainRule:save` — 保存串联规则到 outDir
- `chainRule:list` — 读取 outDir 下的串联规则
- `function:list` — 列出所有可用的运行时函数

### 5.2 ~~desktop/main/preload.js~~ - 暴露新 API
- `dataPoolSave`, `dataPoolList`, `dataPoolGet`, `dataPoolDelete`
- `dataPoolImportCsv`, `dataPoolImportTxt`
- `chainRuleSave`, `chainRuleList`
- `listFunctions`
- 追加到 `window.appApi` 对象
